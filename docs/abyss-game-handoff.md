---

## 0. 三句话

1. 小游戏从「堆叠大陆式牌桌」**转向「搜打撤（extraction looter）」**：高风险高遗物、带入带出、死了掉在原地。
2. **上浮 = 下潜途中往回滚**，会扣生命；越深扣得越狠（借《来自深渊》的上升负荷设定）。
3. **现有代码里生命是死的**——`run.hp` 从来没有被扣过，游戏不会输。这是第一个要补的洞。

---

## 1. 已确认的决策【已定】

| 项 | 决定 | 备注 |
|---|---|---|
| 核心玩法 | **搜打撤** | 搜索 → 风险 → 撤离，死了全掉 |
| 上浮的形式 | **下潜途中往回滚**（现有的 `climb` / curse） | 不是"在站点上选结束" |
| 上浮的代价 | **扣生命** | 越深扣得越狠 |
| 世界观 | **尽量还原《来自深渊》** | 上升负荷、遗物、探窟家、层 |
| 上浮的可行性 | 每层都能浮；**最后几层不给浮，除非特殊遗物** | 特殊遗物是什么待定 |
| 搜索方式 | **点击搜索点** | 不是格子移动 |
| 搜索流程 | 点击 → **读秒** → 才显示物品 | 读秒期间有代价 |
| 背包 | **格子制** | 格数待定 |
| 物品 | **有颜色分级** | 五档 |
| 活物 | **有，但初版不做** | 先只做环境压力 |
| 死亡 | **掉落原地**，位置记下来 | 怎么找回先不考虑 |

## 2. 关键数值【建议，未最终确认】

### 2.1 上浮扣血：按深度的平方

```
每米扣的血 = 0.043 × (当前深度 / 8000)²
```

| 从多深上浮 | 上浮 1,000 米要付 |
|---|---|
| 1,500 米 | ≈ 2 |
| 4,000 米 | ≈ 11 |
| 7,000 米 | ≈ 33 |
| 8,000 米 | ≈ 43 |

**设计意图**：浅水随便上下，深水每一潜上浮都是赌博。这条曲线是"深渊诅咒"手感的核心。

### 2.2 物品五档颜色

| 档 | 颜色 | 名字 | 出现在 |
|---|---|---|---|
| 1 | `#d9d5cc` 白 | 普通 | 浅层 |
| 2 | `#8fbf5a` 绿 | 少见 | 全深度 |
| 3 | `#5aa8e0` 蓝 | 稀有 | 1,500 m 以下 |
| 4 | `#b07ce8` 紫 | 史诗 | 2,300 m 以下 |
| 5 | `#e8b23c` 金 | 传说 | 5,400 m 以下 |

### 2.3 搜索读秒

- 小东西（岩缝、碎石堆、苔藓）：**1.2 秒**
- 大东西（骨骸、遗物匣、石棺）：**2.4 秒**

## 3. 现有代码状态

### 3.1 已经很好的部分

| 文件 | 是什么 |
|---|---|
| `src/scripts/abyss/virtual-scroll.ts` | 接管滚轮、站点点吸附 |
| `src/scripts/abyss/stations.ts` | 4 个站点表 + 深度↔滚动位置反算（二分） |
| `src/scripts/station.ts` | 620 行 Stacklands 式牌桌：一切皆卡、拖卡叠卡 = 动作 |
| `src/scripts/dive-scroll.ts` | 深度映射、区域切换、雷达、**curse 已实现** |
| `src/pages/abyss/dive.astro` | 舞台、HUD、折线、雷达、三段记录 |

**上升诅咒其实已经做了**：`dive-scroll.ts` 里 `climb` 累计 → `curse = clamp01(climb / 0.22)` → 整屏发冷 + 文案升级（超过 0.72 变成「它在往上找你」）。**只差扣血。**

### 3.2 关键缺口

**① 生命是死值（最要紧）**

`station.ts` 里 `const run = { hp: 15, relics: 0 }` 全文只出现三处：

```
 63:  const run = { hp: 15, relics: 0 };
313:  hp: def.id === 'hero' ? Math.max(1, run.hp) : def.hp,
389:  run.hp = src.hp;
```

**没有任何地方扣血，也没有死亡判定。** 凿不动、门压不住、上浮——全都是文案提示，没有后果。

**② 没有带入（装备）**

出发前不能带任何东西。整局的「风险预算」是零成本，搜打撤的紧张感少一半。

**③ 站点 s2/s3/s4 的牌桌是空占位**

只有 s1 有内容可做，其余三层只能一路点下去。

**④ 遗物没有后果**

`relics` 只用来过 s3 的门，拿多拿少没区别。

## 4. 验证性演示（都是独立 HTML，没进仓库）

都在 `_preview/` 目录，用 `python -m http.server 4400 --directory _preview` 看。

| 演示 | 验证了什么 | 结论 |
|---|---|---|
| `abyss-signal-line.html` | 折线横轴改成信号强度 | ✅ 可用。0 米笔直 → 8,000 米断开，作为「信号」表达成立 |
| `abyss-dizzy.html` | 生命值 = 头晕（无数字） | ✅ 四层叠加（摇晃/重影/黑视/泛绿）效果成立 |
| `abyss-loot.html` | **搜打撤主干**：点击搜索 + 读秒 + 背包 + 上浮扣血 + 死亡掉落 | ✅ 跑得通，见下 |

### 4.1 `abyss-loot.html` 里已经验证的三条规则

1. **上浮打断搜索**——读秒期间往上滚，进度清零。
   → 让「我在搜」和「我想跑」互斥，玩家必须二选一。
2. **背包满了必须先丢**，系统不自动替换。
3. **死亡后在地图上标一个 ✕**，记下深度和丢了几件。

### 4.2 演示里发现的一个数不对

背包 **24 格**，搜索点只有 **10 个** → **永远装不满**，"丢了才知道疼"的机制根本触发不了。

两种改法（未定）：
- 背包压到 **8–10 格**（稀缺感强，但频繁打断）
- 或者**大件占多格**（2×2），格子保持 24 ← 更推荐，「装不下扔哪个」更有画面感

## 5. 我发现的一个设计矛盾（需要处理）

**「上浮」和「受伤」现在是同一件事。**

这很优雅（深渊诅咒 = 撤离成本），但有个隐患：

> 玩家每次撤离都在被惩罚，久了会觉得「还不如浮上来之前就死掉」。

**必须有反弹**：撤离成功要有明确的正反馈（结算画面、带回来的东西真的有用）。
否则这套机制会劝退。

## 6. 《来自深渊》设定对照

原作的「上升负荷」就是上浮惩罚的现成依据：

| 层 | 大致深度 | 上升负荷 |
|---|---|---|
| 一层 | ~1,350 m | 头晕、恶心 |
| 二层 | ~2,600 m | 重度恶心、头痛、末梢麻痹 |
| 三层 | ~7,000 m | 呕吐、出血、幻觉 |
| 四层 | ~12,000 m | 剧痛、七窍流血、失去人性 |
| 五层 | ~13,000 m | 失去五感 |
| 六层 | ~15,500 m | 死亡或更糟 |

**现在的四个站点几乎正落在层边界上**（1,500 / 3,000 / 5,000 / 7,000），深度骨架不用改，只要把区名换成层名。

> ⚠️ 上面的深度数字是凭记忆写的，**定稿前请核对原作设定**。

原作没有给出「能抵消诅咒的遗物」的明确答案，这正是「特殊遗物才能浮」的发挥空间——需要自己编一个自洽的解释。

## 7. 待定问题

按优先级：

1. **带入（装备）怎么设计？**
   出发前带什么（氧瓶 / 绳 / 容器），决定待多久、装多少。这是搜打撤的另一半，现在完全没有。

2. **撤离成功的判定和反馈？**
   现在滚回 0 米就算结束，但没有任何结算。要不要一个战利品结算面板？

3. **背包几格？** 8–10 格，还是 24 格 + 大件占格子？

4. **「最后几层不给浮」的例外遗物是什么？** 需要世界观解释。

5. **牌桌（`station.ts`）还要不要？**
   讨论窗口的建议：**保留，但换个位置**——深渊里做搜打撤，**水面/营地用牌桌**（整理战利品、合成、决定下次带什么）。
   这样 620 行代码不用扔，而且语义对上了（原作里探窟家就是在奥斯镇整理遗物）。
   **这条没有被确认，需要拍板。**

6. **死掉的东西怎么找回？** 用户明确说"先不考虑"，但 ✕ 标记已经在演示里画了。

## 8. 建议的实施顺序

1. **把 `run.hp` 接上因果**——上浮扣血 + 死亡判定 + 掉落。这是最小可玩闭环。
2. 加上**带入**（哪怕只有"带几个容器决定背包大小"）。
3. 加**撤离结算**（正反馈）。
4. 再做背包容量 / 大件占格。
5. 最后才是活物、特殊遗物、找回尸体。
