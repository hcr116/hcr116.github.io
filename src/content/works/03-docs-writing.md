## 说明

这个作品用来演示**文档下载区块**：详情页底部会列出所有附件，点击在新标签页打开。

真实使用时，把 PDF 文件放进 `public/docs/` 目录，然后在 frontmatter 的 `docs` 里登记即可：

```yaml
docs:
  - label: 组件库使用说明 v2.1
    href: /docs/component-lib.pdf
```

## 为什么文档也算作品

因为写文档比写代码更容易被低估，而它恰好能证明一件代码证明不了的事：**你能把自己的东西讲清楚**。

一份好的说明文档通常包含：

1. 这段代码解决什么问题（不是它用了什么技术）
2. 最小可用示例 —— 复制就能跑的那种
3. 常见错误和对应的报错信息
4. 什么时候**不该**用它

第四条最容易被漏掉，也最能体现作者真的用过自己写的东西。

## 结构上做了什么

- 把原来按模块划分的目录，改成按使用场景划分
- 每个 API 都补了「不这么写会怎样」的反例
- 加了 12 个可以直接复制的代码块
