## 0. 先分清两条线（别混在一起看）

| | **线 A · 阿比斯（游戏）** | **线 B · 作品集（网站）** |
|---|---|---|
| 是什么 | 一个想做的游戏 | 个人作品与经历的展示页 |
| 现在的载体 | 网站上的 `/abyss/` 与 `/abyss/dive/` | 首页、作品、文章、时间线、关于 |
| 目的 | 做一个完整作品 | 让别人快速认识我 |
| 状态 | **只有氛围外壳，玩法未定** | 框架完整，内容待填 |
| 谁在用 | 玩家 | 招聘方 / 同行 / 访客 |

**共用资产**
- 一套视觉语言：深色、信号、下潜、米数、记录
- 一个世界观种子：「阿比斯是接进来的一路信号」

**两者的关系**
> 网站上那个阿比斯，是游戏的**先导片 / 概念验证**，不是最终形态。
>
> 它先把气氛做出来，验证「这个味道对不对」，再决定游戏到底做什么。
>
> 所以：**网站上做得再花，也不等于游戏做出来了。** 反过来说，游戏的核心一定能在网站这一点点篇幅里尝到味道，否则说明还没想清楚。

## 2. 线 A · 游戏

### 2.1 还没回答的问题（先列出来，不急着定）

1. **类型**是什么？探索／解谜／叙事／恐怖／下潜模拟？
2. **视角**？第一人称下潜、2D 侧视剖面、还是俯视？
3. **核心循环**：玩家每次下潜要做什么、能带回什么？
4. **深度是资源还是进度？** 有没有氧气／压力的倒计时？
5. **记录是谁写的？** 玩家是继承者，还是作者本人？
6. **「更深处」到底是什么？** 结局是「到底」还是「永远没到底」？
7. **规模**：20 分钟的短篇，还是能做几个月的东西？
8. **引擎**：UE5？Godot？还是继续 Web（Three.js）？

### 2.2 三个可能的方向（备选，都还没定）

#### 方向 1 · 下潜模拟（最贴合现在的氛围）

- 第一人称，操控一台往下的探测器
- **深度就是资源**：下得越深，回程越难，必须在「再往下一点」和「回得去」之间做选择
- 每次下潜带回「记录」，记录拼出真相
- 参考氛围：《SOMA》的孤独 + 《Subnautica》的压迫感，但**去掉生存建造**
- 规模：小而完整，2–4 小时

> 优点：和现在网站的氛围 100% 对齐。
> 风险：第一人称 + 深海 = 最容易做成「走两分钟就腻」。

#### 方向 2 · 剖面解谜（最省成本）

- 2D 侧视，玩家在一条竖井里规划路线
- **现有那条红色崎岖折线本身就是解谜界面**：路线选择决定这一潜看到什么
- 每次下潜是「一局」，可以反复刷不同路线
- 规模：可以做得非常小，甚至网页就能跑

> 优点：成本最低、最快出可玩版本、最能验证核心玩法。
> 风险：容易变成「一关卡一关，没有阿比斯的味道」。

#### 方向 3 · 叙事装置（最接近现在的网站）

- 不是「玩」，是「读」：一个可以反复下潜的叙事空间
- 每次下潜看到不同的记录片段，顺序和深度可变
- 规模：一个月能做完，本质是高级互动小说

> 优点：门槛最低、最容易做完、最容易放进作品集。
> 风险：「互动小说」在作品集里说服力不如「真游戏」。

### 2.3 从网站能直接搬到游戏里的资产

| 资产 | 复用到游戏 |
|---|---|
| 五区域命名 + 深度段 | 直接就是关卡分段 |
| `ROUTE_PATH` 下潜剖面 | 可以变成关卡地图／路线选择界面 |
| 深度 HUD + 危险等级 | 直接就是 UI |
| 三条记录文本 | 直接就是叙事素材（可以扩到 7 条） |
| 雷达扫描 + 回波 | 可以变成「侦测」玩法 |
| 无光带 + 手电筒 | 直接就是光照机制 |
| 音效系统 `sfx.ts` | 直接就是声音设计 |
| 下潜转场 `dive-transition.ts` | 可以直接就是「一潜开始／结束」 |

## 3. 线 B · 作品集：三层想法（先归档，慢慢做）

> 这些是**网站侧**的增强，和游戏无关。别和上面混。

### A 层 · 把下潜变成内容载体

- **深度 = 时间轴**：每 1000 米 = 一年，滚到某层浮现那年的项目与想法
- **沉船 = 作品**：每个作品是海底一个「发现物」，雷达扫到才浮出卡片
- **压力 = 心力**：越深的作品越「重」（投入最大、最难的那个压在最底）

> 意义：把简历从「列表」变成「打捞」，同一批作品两种讲法。

### B 层 · 把「信号」设定做透

- **低频偶发干扰**：任意页面，每分钟最多一次，文字抖一下，浮出「下面还有东西」
- **全站信号强度条**：顶部一条极细的线，越接近 `/abyss/` 越弱
- **404 = 掉进更深处**：「这一段信号丢了」
- **标签页标题衰减**：越往下 `document.title` 越乱、最后变空

> 意义：让整站变成「有世界观」的作品集，而不是「好看的页面 + 一个彩蛋」。

### C 层 · 交互与感官

| 想法 | 说明 |
|---|---|
| **3000 米以下开手电筒** | 无光带之后只有鼠标周围一圈可见（视觉冲击最强的一处） |
| **下潜的抵抗感** | 5000 米后继续滚，页面反向走一点；过 6000 米抵抗消失 |
| **心跳同步** | HUD 心跳从 72 降到 40，用 WebAudio 实时合成低频 |
| **越深越失焦** | 色差、噪点、轻微模糊随深度递增 |
| **氧气倒计时** | 显示「你还能待 N 分钟」，但永远够用（纯心理装置） |

### D 层 · 内容型玩法

- **7 条记录做满**（现在只写了 3 条：01 / 07 / ?）
- **收集解锁「更深处」**：集齐才开门，而不是永久死锁
- **和文章页联动**：读完所有文章才能下到 8000 米（`articles-unlock.ts` 已存在）

### E 层 · 技术炫技（风险最高，慎入）

- **Canvas 深海粒子**：洋流、发光生物、浮尘。纯 canvas 就够，别上 three.js
- **真 3D 竖直隧道**：Three.js 相机下降。**建议不做**——移动端会掉帧，作品集不需要

## 5. 一条设计原则（写给未来的自己）

> **别让阿比斯比内容精致太多。**

访客点进来，第一眼会被阿比斯震到；第二眼发现「作品」栏还是占位符，印象会立刻从「这人很牛」变成「这人很闲」。

所以每次想给阿比斯加特效之前，先问一句：**作品页填满了吗？**
